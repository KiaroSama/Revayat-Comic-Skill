# Source-aware Persian dialogue review

Read this when a draft sounds translated, a speaker's register drifts, a short
reply is ambiguous, or a fitted line risks losing meaning. Work on the current
region with its overview, crop and freshly built adjacent context. Existing
locked glossary, title policy and recorded relationships remain authoritative.

## Review route

1. **Source draft.** Settle the speaker, addressee, referent and scene first.
   Preserve agency, time, negation, conditions, quantities and emotional force.
   Write the full meaning before considering the balloon's size.
2. **Persian-only read.** Read the draft without the source wording in view.
   Would this speaker say it to this person? Read it aloud silently: remove
   translation-shaped phrasing only where the same claim and emphasis survive.
   Dialogue, thought and narration can have different voices; formality follows
   their established relationship, not age, gender or loudness.
3. **Final source comparison.** Compare every edited line with the source and
   answering panel again. Recheck who did what, not-yet versus never, permission
   versus obligation, irony, numbers/units and approved names. Fluent Persian
   that changes one of these is still a failed translation.
4. **Suggest, then accept.** Record `region`, evidence, proposed wording and
   any meaning risk in the review note/activity log. These are suggestions,
   not approval. Apply accepted changes through the existing worksheet flow.
   For shortening keep `fa_full:` and compare it with the actual displayed
   `fa:` before accepting `compressed-variant`; fit remains a layout check.

## Carrying a prior decision

Generated `reviewed: code@<fingerprint>` values refer to the exact source,
source revision and displayed wording already reviewed. Editing either wording
or source does not approve it again: compare the current pair and use the bare
code only for a new explicit decision. Direct stored-text edits also reopen modern
lint decisions. Legacy records keep direct compatibility, but an old half-space
review is not carried over newly introduced ambiguous spans. Compression review
additionally binds full wording and layout. A matching stamp is not linguistic
truth or reviewer authentication.

After a box correction, inspect refreshed crops/panel order before using adjacent
dialogue to infer a referent or speaker. Wording-only edits preserve manual spatial
choices; moving a region does not identify who is speaking.

## Cases that need source evidence

- A negative question's short answer: translate the intended proposition, not
  an isolated yes/no token. Keep the answering balloon's evidence in view.
- An idiom: choose its scene meaning; the same words may be literal in another
  panel. A context-sensitive phrase is not a permanently locked glossary term.
- Register: preserve an unanswered request to switch from formal to familiar
  speech as a request, not an already accepted relationship change.
- Measurements and protected strings: keep the number, unit and exact technical
  label when they identify the object. Typography fixes do not authorize changing
  a version, identifier, URL, formula or code fragment.

Unsettled referents or register stay explicit questions in `note:`. A second
model may advise, but neither agreement nor back-translation is certification.
The original `review-*` controls in the evaluation set distinguish deterministic
number/term checks from human-only semantics; candidates await bilingual review.
