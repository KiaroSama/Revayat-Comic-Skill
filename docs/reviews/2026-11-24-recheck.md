## Confirmed repair scope

### R01 — Pattern-painted PDF stencils lose native resolution

MuPDF reports an image stencil painted using a tiling pattern through
`clip_image_mask`, whereas the density device registered only `fill_image` and
`fill_image_mask`. A 1000 × 1000 stencil on a 100 × 100-point page therefore
rendered at 100 × 100 pixels at 72 DPI. A 100000-pixel budget was accepted even
though preserving the source required 1000000 pixels.

Register and measure the clipping callback with the same affine and nested-mask
logic. Regression fixtures cover direct and nested Form placement, pattern and
solid paint, exact visible pixels, and refusal before raster allocation when
the native pixel budget is exceeded. Keep faint images, shear and soft-mask
controls from the preceding audit.

### R02 — Source-less legacy batch documents cannot merge unchanged

Planning adds a local `source.page_count` to each shard. The shared-input hash
removed that count but compared an empty source object against an absent source
object, rejecting an otherwise untouched legacy chapter.

Normalize only absent/empty source metadata after removing the local count.
Keep meaningful source fields and every glossary/policy guard authoritative.
Verify unchanged merge, exact replay, and source drift on both the canonical
chapter and worker sides without modifying either document on refusal.
Recognize the exact previous shared-hash representation of the canonical
document for in-flight manifests; compare workers using normalized inputs.
The complete frozen document and asset checks still authorize every write.

### R03 — Historical stage counters break planning and recomputation

Older crop stages stored an integer `pages` count, not a map of page revisions.
Batch slicing, merging and stage stamping incorrectly applied mapping methods
to it. Recomputing a worker also removes obsolete `meta.stage_seq`, which is
bookkeeping rather than a shared translation input.

Treat historical counts as unverified evidence, retain untouched legacy
records, ignore only retired stage bookkeeping in the shared digest, and
promote current evidence only for the worker's owned pages. Cover all-worker,
last-worker and selected-page recomputation, exact replay, and exclusion of
cross-shard freshness claims. Never infer that untouched pages were rerun.

### R04 — Published binary ZIPs omit their advertised CLI reference

All four v1.2.0 release archives include the repository README, whose CLI
reference link points to `rust/revayat-comic-cli/README.md`. That file is missing
from each archive, leaving offline users without the JSON schemas, limits and
exit-code reference. The command help does not supply those schemas.

Include the exact reference path in the release packager. Run the real packaging
Python from the workflow against all four platform names; verify the linked
file, unchanged binary bytes, executable mode, publisher metadata and ZIP
checksum. Do not mutate already published signed v1.2.0 artifacts. The next
authorized release must be built from the verified integrated commit.

### R05 — Untouched batch replay still republishes identical assets

The integrated replay fix handles changed worker output. If an untouched merge
leaves the canonical document identical to the frozen base, `_check_snapshot`
returns from its frozen-base branch before testing whether the complete result
is already present. Repeating the merge therefore invokes `_publish` again.

Check exact resulting document bytes and all expected asset hashes first.
Only a real change from the frozen base may reach publication. A failing
`_publish` sentinel verifies untouched replay; the prior changed-output replay,
newer canonical answer, modified-asset and transaction controls remain active.
